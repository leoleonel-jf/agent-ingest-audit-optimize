# The cut: `compliance` withdrawn, the roadmap closed, four tools made optional

Status: approved 2026-11-18 (review decisions in `docs/reviews/2026-11-18-revisao-do-plugin.md`, finding 1 and decision 3)
Target version: 0.8.0
Phase: fifth increment of the 2026-11 review

## 1. The problem

The plugin grew faster than anyone used it. Nine commands ship; the Skill requires several of
them on every audit; and one of them, `compliance`, states things about a regulation and a
standard that are wrong. The review's decision was to cut, in three parts.

## 2. `compliance` is withdrawn

### What was wrong

The review found, and the reviewer of the review confirmed against the official text, that the
shipped control mapping misidentifies what it maps:

- `eu-ai-act.json` labels Article 13 as human oversight. Article 13 is transparency and
  information to deployers; human oversight is Article 14. The same error is in
  `references/COMPLIANCE.md`, in `iso-42001.json`, in the module docstring and in the 0.5.0
  changelog entry;
- `iso-42001.json` names `A.6.2.6` as logging (it is operation and monitoring; event logs are
  `A.6.2.8`), `A.7.3` as access management (it is acquisition of data), and `A.8.1`, which does
  not exist. It ties risk to controls through clause 8.2 where the standard uses 6.1.3 and 8.3.
  The ISO control titles were only ever checked against secondary sources;
- the application date the module and the changelog give, 2 August 2026, no longer holds for the
  obligations the mapping is about: Regulation (EU) 2026/1744 moved them;
- `retention_days: 180` is shorter than six months.

A tool that inventories evidence "against Article 13" while meaning Article 14 produces a report
that reads as careful and is wrong at the first line an auditor checks. Correcting the mapping
would mean owning a legal reading this project has no standing to maintain. So the command goes.

### What happens to the command

`dashboard.py compliance` stays a registered subcommand and still accepts its old arguments, so an
existing invocation fails with an explanation instead of an argument error. It does nothing else:

- it prints one notice on stderr saying the command was withdrawn in 0.8.0, why, and where the
  record of the errors is;
- it reads no ledger, writes no file, and prints nothing on stdout, with or without `--out`;
- it exits `2`, the code this bundle uses for "nothing was produced".

Removed from the bundle: `assets/compliance/` (both mappings), the evaluation code in
`ledgerlib/compliance.py`, and `references/COMPLIANCE.md`. `SKILL.md` keeps one sentence: the
plugin does not assess regulatory compliance, and nobody is to be told a ledger shows it.

### What is preserved

Nothing that already happened is rewritten. The 0.5.0 changelog entry, `docs/releases/v0.5.0.md`,
and the spec and plan of the feature stay as written, errors included; the 0.8.0 entry is where
they are corrected. Evidence packs a user wrote with `--out` are their files and are not touched.
No ledger record is deleted or altered: the command only ever read them.

## 3. The roadmap is closed in writing

`docs/ROADMAP.md` promised pillars II and III. What was not built is now marked abandoned, each
item by name, with the date and the decision, so nobody reads the file as a plan. The original
text stays underneath as history. Three items are kept as candidates, not commitments: a digest
for hook scripts, more clients, and more languages on request.

## 4. Four tools leave the Skill's default path

`scan`, the dashboard (`build`, `update`), `lock`, and the chain seal keep working and keep their
tests. What changes is `SKILL.md`: none of them is something the agent runs on its own any more.

- The instruction to seal the chain "as routinely as you run `verify`" is removed. Sealing becomes
  something to do when the user asks for tamper evidence.
- `lock`, `build` and the whole "capture a baseline of an unknown client" section move under one
  heading, "Optional tools", that says they run on request. The guidance that keeps them safe when
  they do run (never read an empty generic baseline as clean, never guess a path, never call a
  sealed ledger tamper-proof) is kept word for word.
- `verify` stays in the default path: it is the validator, and a ledger that was written is a
  ledger that gets checked.
- `drift` and `rollback-preview` keep their conditional places. Both already run only when a
  baseline or a recorded run exists.

Making the Skill itself shorter and reordering it around the new focus is the seventh increment,
not this one.

## 5. Tests

- The withdrawn command: exits `2`, names the version and the reason on stderr, prints nothing on
  stdout, creates nothing under `--out`, and does not open the ledger (it succeeds in refusing
  even when the ledger path does not exist).
- The bundle: no `assets/compliance/` directory and no `references/COMPLIANCE.md` in either
  archive; `SKILL.md` links to no file that is not shipped.
- `SKILL.md`: the sentences that made sealing routine are gone; the optional heading exists and
  holds `scan`, `lock`, `build` and the seal; the three safety sentences survive.
- The roadmap: every abandoned item is named under the dated heading.
- Each new guard is ablated.

## 6. Out of scope

The Skill rewrite (increment 7), plugin formats and `/dashboard` (increment 6), the rename
(increment 8). `rollback --execute` was never built; it is abandoned in the roadmap and needs no
code change.
