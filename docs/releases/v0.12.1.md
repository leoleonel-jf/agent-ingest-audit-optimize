# Plugin Reviewer v0.12.1

`drift`, `rollback-preview` and `lock` now read a ledger whose `client` is not an adapter name,
instead of stopping with "unknown client".

## What changes for you

Ledgers written before adapters existed (July 2026) recorded the client as free text, such as
"Codex Desktop / Codex CLI". Until 0.12.0 the three commands that read a ledger's client stopped on
such a ledger with exit `2`, and the Skill had to check files by hand. From this version:

- an adapter name selects that adapter, as before;
- free text that names exactly one client, as a whole word with a hyphen read as a space, selects
  that adapter, and a note on stderr says so;
- free text that names none or several clients falls back to detection, with a note naming the text
  and what it matched;
- `--client` typed on the command line stays strict: a wrong name is still a tool error.

Runs recorded before anchors existed name absolute paths and no backup path. Their targets stay
`UNVERIFIABLE` and their rollback indicator `BROKEN`: this version cannot restore what was never
recorded. It helps the runs recorded from now on in such a ledger, which keep its old `client`.

## Changes

- **`ledgerlib/adapters.py`**: `select_adapter_detail` takes `ledger_client`, read after
  `--adapter` and `--client` and never raising;
- **`ledgerlib/drift.py`, `rollback.py`, `lock.py`**: pass the ledger's client as `ledger_client`;
- **`references/LEDGER_BASELINES.md`**: the rule, under The unknown client;
- **tests**: `dashboard/tests/test_legacy_ledger_client.py` (12 tests, each guarded piece proved by
  ablation); one test in `test_drift.py` that pinned the old exit `2` now pins the report.

No ledger field, identifier, label, or schema changed. A ledger written by 0.12.0 verifies under
0.12.1 and the reverse.
