# Agent Ingest, Audit & Optimize v0.7.0

The bundled adapters, re-verified against the vendors' documentation, and a way for `update` to
refuse a baseline taken with stale evidence.

## Changes

`docs/specs/2026-11-19-adapters-reverified.md`, with the evidence in
`docs/research/2026-11-19-client-configuration-paths.md`.

- **The three adapters are current again, until 2027-02-17.** They expired on 2026-10-28. The date
  moved only after every declared path was reopened in the documentation;
- **Claude Code: `.claude.json` is read where the client keeps it**, under `CLAUDE_CONFIG_DIR` when
  that is set. A baseline taken by an earlier version names those items `$HOME/.claude.json`, so
  the first `drift` after upgrading reports them as removed and added again;
- **Claude Code: `~/.claude/settings.local.json` is no longer probed as user settings.** It is
  documented as a project file only. Scan with the home directory as the project to capture it;
- **Claude Code: `AGENTS.md` is probed.** The client reads it since v2.1.277 when no `CLAUDE.md` is
  present. The probe records the file, not whether a session loaded it;
- Claude Code also gains managed `CLAUDE.md`, `managed-mcp.json`, managed skills and subagents,
  and project-level `agents/` and `commands/`;
- **Codex: MCP servers, plugins, hooks, rules and custom agents are probed for the first time**,
  along with `requirements.toml` and the Windows system directory;
- **Codex: skills no longer declare a winner.** Two skills with one name both appear;
- **`update` reports findings as data**: a `findings` list of `{"code", "message"}` in its JSON
  summary;
- **`update --strict` writes nothing when the scan reports a finding**, and says
  `"refused": "strict"`. Without the flag nothing changes.

What both clients read and the adapters still do not probe is listed, with reasons, in the
research document.
