# Agent Ingest, Audit & Optimize v0.4.0

The dashboard: `dashboard.py build` and a self-contained HTML shell, dogfooded with zero defects
found.

## Changes

`docs/plans/2026-07-31-dashboard-0.4.0.md` and `docs/specs/2026-07-31-dashboard-build.md`.

- adds `dashboard.py build LEDGER [--out PATH] [--lang CODE] [--force] [--project PATH]
  [--adapter FILE] [--user-config PATH]`: assembles the nine-panel payload by calling the same
  `drift` and `rollback-preview` code the standalone commands run — same code, not similar code.
  The gate is `verify`'s own: a ledger `verify` would reject fails the build with `verify`'s exit
  semantics and writes nothing. Writes exactly one file, atomically (temp file, then rename), and
  refuses to overwrite an existing `--out` unless that file already carries the shell marker
  `id="aio-payload"` (`--force` overrides). The payload serializer escapes every `<` (and
  line/paragraph separator) as a `\u00XX` sequence unconditionally, over the entire serialized
  envelope, so ledger content can never close the payload's `<script>` tag early; the
  static-injection recipe for no-Python clients repeats the same escaping step by hand;
- ships `dashboard.html` as a single self-contained template: nine panels (overview, inventory,
  changes, provenance, rollback, backlog, decisions, materials, help), a strict
  `Content-Security-Policy` (`default-src 'none'`), and rendering that touches the DOM only through
  `textContent`, never `innerHTML`. `dashboard/tests/test_shell.py` boots the real shell against a
  DOM stub and runs it under Node, so the runtime behavior a browser actually executes is pinned,
  not just Python fixtures. Two UI languages ship, `en` and `pt-BR`; operating states, drift states,
  rollback indicators, classifications, statuses, and record ids stay in English in both languages
  as canonical vocabulary. The action model is a fixed English template plus a validated record id
  — four templates, nothing else reaches the clipboard path — with an in-memory queue, a
  per-record/per-preview JSON export, and a two-step rollback confirmation. A command palette
  (`Ctrl`/`Cmd`+`K`) indexes every record. The page is legible without color, usable at 360px,
  printable, respects `prefers-color-scheme: dark` and `prefers-reduced-motion: reduce`, and issues
  zero network requests — verified in real Chrome and headless Edge;
- narrows three things on purpose: **Open** links render only where the payload carries an actual
  resolved filesystem path (known projects' `project_root`/`ledger_path`) — a 0.5.0 candidate
  extends this on the Python side (spec §8). **Export** is per-record/per-preview JSON, not a
  ledger-wide download. **Staleness** is the dashboard's own generation age, not a true
  newer-than-the-file-on-disk comparison, because a `file:` page cannot stat `ledger.json` without
  issuing a request and the zero-network property is the point of a generated dashboard;
- adds three §17 eval cases — XSS-001, CLP-001, NET-001 — bringing the suite to 33 cases, and a
  packaging test proving both distribution zips ship the dashboard shell templates;
- dogfooded against a real project ledger in a real browser and headless Edge: all six design-spec
  §16 acceptance criteria pass, and no defect was found — the first increment whose dogfood
  confirmed rather than discovered. Full record in `docs/validation/dashboard-dogfood-0.4.0.md`.
