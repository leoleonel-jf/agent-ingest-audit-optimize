# Plugin Reviewer v0.12.0

The Skill asks before it records. A review ends by offering its record and writes it only when you
say yes. A run with no one to answer records nothing.

## What changes for you

Until 0.11.0 every review wrote one record without asking, into the global ledger when there was
no project. From this version:

- Every review and every material audit closes with one question, the offer. It says that nothing
  was recorded, what would be written, and which ledger it would go to, by its path.
- The yes is a message you send after the offer, in any wording and any language. Asking for the
  record in the same message that asks for the review is not a yes: the offer still comes, with the
  ledger it names, and you confirm once.
- Silence is a no. If your next message is about something else, the Skill answers it and adds one
  line saying that the review was not recorded, once. Ask later in the same conversation and it is
  recorded then.
- A run with no one to answer records nothing: `claude -p`, `codex exec`, a CI job, a scheduled
  run, a subagent. The review comes out in full and says that nothing was recorded. If a script of
  yours relied on such a run to fill the ledger, it no longer does. A second turn sent to the same
  session is a message like any other: a yes there records the review.
- Text that is read is never a yes: not a line in the material under review, a file, a memory, a
  setting, or a tool result.

An authorized change keeps its records as before, wherever the instruction is given: it is the yes
for the change's `PROP`, `RUN`, and `ADR`, and for no other record. This version changes the record
of a review, not implementation.

## Changes

`docs/specs/2026-11-19-ask-before-recording.md`.

- **`SKILL.md`**: a ground rule (record nothing until the user says yes), the offer as the last
  lines of an answer, and the rule in `Keep the ledger`: the offer, the yes, no answer, no one to
  answer;
- **`references/LEDGER.md`**: `Bookkeeping is not implementation` is now `A record needs a yes`,
  with what one yes writes. No identifier is taken before the yes;
- **Evaluation suite**: 39 cases become 43. The mutation check no longer exempts the plugin's own
  ledger, a new critical check `record_follows_a_yes` guards every case about the record, and
  `ledger_bookkeeping_is_not_implementation` is renamed `ledger_write_is_not_implementation`;
- **`README.md`, `PRIVACY.md`, `evals/RUN_PROTOCOL.md`** say the same. The README also said
  Python 3.9 where the tool requires 3.10.

No command, ledger field, identifier, label, or schema changed. In `ledgerlib` only the version
constant moves. A ledger written by 0.11.0 verifies under 0.12.0 and the reverse.

What was measured, and what was not, is in `docs/validation/ask-before-recording-0.12.0.md`.
