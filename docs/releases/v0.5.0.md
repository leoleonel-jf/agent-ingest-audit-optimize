# Agent Ingest, Audit & Optimize v0.5.0

Five increments: the highest-precedence settings layer is read at last, the ledger's own records
are hash-chained, the ledger is mapped to named regulatory controls, and a baseline can be pinned
as `agent.lock`. Three of them state their limit before they state their feature.

## Changes

`docs/plans/2026-07-31-*.md` and `docs/specs/2026-07-31-*.md`, one pair per increment.

- makes **Open** true everywhere the design spec promised it, closing the first of the three
  deliberate narrowings the 0.4.0 spec recorded: every drift and rollback-preview row now carries
  the resolved `path` its anchor produced, from one helper both commands share. `path` is `None` —
  never a raise — for a non-string anchor, a glob pattern, or an anchor the path-safety layer
  refuses, because that refusal is already the row's classification. A `MISSING` row keeps its
  path: "which file is gone" is what that row's reader asks next. The anchor stays the visible
  text everywhere; the link is an action beside it, never a rewrite of it;
- probes the managed policy layer — the layer that overrides command line, project and user, and
  that the user cannot override — which nothing had ever looked at. The adapter format gains one
  token, `$platform:<system>:<path>`, skipped **textually, before any filesystem call** where it
  does not apply; a malformed guard is a finding, never a silent skip, because a typo would empty
  a whole layer and read exactly like a clean one. The Windows path that lost support in v2.1.75
  is probed as an **expected absence**, so dead policy an administrator believes is live shows up
  if it reappears. Still not probed, and not guessed: managed policy for Codex and the Windows
  registry keys, neither of which has a verified primary source;
- distinguishes *not applicable on this platform* from *unresolved*: an anchor whose candidates
  were all platform-skipped now yields **no items and a note**, rather than a permanently clean
  layer nobody ever read. Each entry records the `sys.platform` that produced it;
- hash-chains the records, so tampering leaves evidence. Each record may carry
  `chain{index, previous, digest}`, with index and previous deliberately inside the hash. The
  limit ships in the same words as the feature: this is tamper-**evident**, not tamper-proof —
  editing, deletion and reordering are detected, a wholly rewritten and re-sealed chain is not,
  which is why `chain --head` prints a digest to record outside the ledger and
  `verify --chain --expect-head` compares against it. Unchained records stay valid, `--seal`
  refuses to reseal over a break, and sealing preserves indentation and line endings;
- maps ledger artifacts to regulatory controls with `dashboard.py compliance`, as evidence and
  **never as a claim**: three values, none of them "compliant", and a test greps every report and
  mapping for the claim word. Mappings are declared data with a verification date, and an expired
  one is refused rather than warned about. `eu-ai-act` and `iso-42001` ship;
- adds `agent.lock`: `lock --from BASE-YYYY-NNN` pins the installable artifacts, `lock --check`
  compares. Byte-deterministic by requirement, and `--check` reads **nothing** from the
  environment — `drift` is the command that asks about the disk. A green check says nothing
  changed since the pin; it says nothing about whether what was pinned is trustworthy, and eval
  case `LCK-001` fails any answer that confuses the two. The suite grows to 34 cases;
- amends the design spec's non-goals in the open as **ADR-2026-001**, keeping the original list
  visible: `serve` is allowed only loopback-bound, read-only and in the foreground; a ledger may
  import others read-only, with the single-writer rule untouched. `rollback --execute` is
  explicitly **not** authorized.
